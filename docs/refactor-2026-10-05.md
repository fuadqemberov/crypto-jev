# Adaptive paper execution refactor — 2026-10-05

Baseline: `516662e` (master). This note records implementation decisions, not a claim of profitability.

## Findings before implementation

1. **Priority starvation**: `Engine.scan()` visited every symbol behind six semaphore slots; its next
   pass waited for the entire universe plus the configured sleep. Signals already published incrementally,
   so “nothing publishes until the full scan ends” was not the actual bug. Revisit latency and slow AI
   could nevertheless exceed a 120 s signal lifetime.
2. **Unsafe uncertainty semantics**: low-confidence leverage was translated into a 100× JEV cap.
   The executor still capped at 20×, but uncertainty removed a constraint rather than vetoing entry.
3. **Unused technical score**: `technical()` computed weighted trend/momentum scores and the UI displayed
   them; `decide()` did not consume them. The refactor removes scoring and retains explicit guards.
4. **Partly implemented performance work**: bulk quotes, closed-candle feature caching, shared Binance
   pacing, dynamic RemotePairList, immediate per-row publication and background bridge fetching already
   existed. These have been preserved and extended; they were not all newly added here.
5. **Risk drift**: daily loss used the original wallet, sizing used an approximate cost fraction,
   risk constants were repeated, and funding guards existed but funding was absent from R:R/sizing.
6. **Insufficient bridge observability**: v2 included timestamps but lacked executor risk heartbeat,
   configuration agreement, retry backoff, acceptance diagnostics and a health endpoint.
7. **Process/restart limitations**: SL/TP depended on Freqtrade staying alive. Persisted trade plans existed,
   but stop restoration repeated every loop. Cache was volatile FIFO. Analysis and trade DBs already persisted.

## Design and policy choices

- Keep two processes and JEV-only direction. Volume only schedules work; it never creates direction.
- Separate full radar and priority lanes, reserve concurrency for the latter, bound task creation and
  suppress duplicate in-flight symbols. Open positions are never truncated by watchlist size.
- Keep timestamps truthful: bounded symbol deadline plus post-AI context revalidation. Do not fix expiry
  by assigning “now” to old data. Cache hits must match semantic context and closed candles and remain within TTL.
- Remove unused scoring instead of adding an arbitrary entry threshold. Diagnostic indicators remain visible.
- Make uncertain leverage WAIT. Independent CLOSE confidence permits a configurable softer exit threshold.
- Use current marked equity, not a rolling high-water mark. Realized daily loss plus negative open PnL is
  conservative and reconstructable from persisted Freqtrade history after restart. Positive unrealized PnL
  does not offset the realized loss term. UTC-day semantics are explicit.
- Preserve old stop tags and tighter stops. Restore once after framework initialization, then use the
  persisted stop rather than an indefinitely replayed in-memory dictionary.
- v3 is a coordinated protocol upgrade. Old processes fail closed; no silent v2 compatibility that drops
  the new risk/heartbeat requirements.

The executor receives validated **bulk mark prices through the bridge**. Equity calculation does not
issue one exchange request per open trade per callback. Mark timestamps must be within 15 seconds;
missing/stale marks block new entries while independent stop/target callbacks continue.

## Validation

- Python 3.12.14; real Freqtrade 2026.8 strategy resolver, configuration schema and SQLite persistence API.
- **178 tests passed**; `node --check app/static/app.js`, `node --check tests/operations-ui.cjs`,
  Python compileall and `git diff --check` passed. One upstream Starlette/httpx deprecation warning remains.
- Unit/integration suite uses deterministic mocked exchange/JEV responses; no real keys and no orders.
- 500-symbol scheduling regression: a blocked full radar does not prevent priority publication.
  One local run measured **0.18 ms** for the mocked priority work. This only measures scheduler isolation,
  not Binance/JEV performance, fill latency, or profitability.
- Budget invariants are exercised across multiple equities, stop distances and requested leverages.
- Old trade tags, tighter LONG/SHORT stop restoration, unchanged migration DB/credentials/pairs, NaN/Infinity,
  future timestamps, missing heartbeat, stale marks, duplicate signals, daily loss and cooldown are tested.
- Browser test is provided in `tests/operations-ui.cjs`, but was **not completed** in this environment:
  Chromium was absent and its download returned an invalid archive. Visual browser QA remains outstanding;
  JavaScript syntax checks passed. This is separate from the passing backend suite.

## Remaining limitations

1. No live exchange/JEV soak or profitability benchmark was run. More frequent analysis does not imply better trades.
2. Binance weight limits and JEV latency can still exceed a priority budget, especially with many open positions.
   UI reports overload; stale data remains blocked. There is intentionally no limit on open position count.
3. Funding reserve is based on current rate and a configured number of periods; it is not a future settlement forecast.
4. Daily loss is a current-equity threshold, not a persisted high-water drawdown or portfolio correlation model.
5. SQLite operations are synchronous with a bounded busy timeout; persistent AI caching adds writes and is opt-in.
6. Heartbeat, HTTP connection reuse and systemd supervision improve detection/recovery but cannot execute SL/TP
   while the Freqtrade process or host is dead. A hung process requires external alert/recovery policy.
7. Rejection counters describe attempts and are process-local; analysis/trade histories remain persistent.
8. No news, on-chain or order-book-depth AI plugin was added. These inputs remain marked unavailable.

## Migration contract

Existing `.env` values win over profile defaults. `--upgrade` must be run after risk or poll settings change,
then both processes must restart together. `analysis.db` receives an additive cache table/index; the Freqtrade
trade database is untouched. No wipe, wallet reset or forced position close is performed. Back up files while
processes are stopped and account for the temporary loss of process-level stop supervision during restart.
